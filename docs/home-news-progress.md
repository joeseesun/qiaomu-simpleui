- User requirement: pairing/transfer must work without Obsidian, and private keys must not live in a vault, source repository or temporary client profile. - Research: [Apple recommends Keychain for passwords/cryptographic keys](https://developer.apple.com/documentation/security/storing-keys-in-the-keychain); [Windows provides native Credential Manager operations](https://learn.microsoft.com/en-us/windows/win32/api/wincred/nf-wincred-credwritew); [Linux Secret Service](https://specifications.freedesktop.org/secret-service/latest/) defines a desktop credential service. Use native device-local storage without plaintext fallback. Non-secret device IDs/mode/addresses/fingerprint references belong in user application data, independent of vault IDs; no private key in that metadata.
- Acceptance for the independent component: on-demand native pairing/discovery/verified transfer; stable device identity and pinned host verification; credentials persist across process restarts, changing/closing/deleting vaults and client reinstall; missing/locked storage is distinct from network/auth failure and never silently regenerates an identity; one-time legacy migration verifies the device key before changing references and retains a recovery path until independently re-read. Public client APIs expose pairing/status/send, not raw credentials. Ship a self-contained client for users without Obsidian; do not require Calibre for native EPUB conversion.
